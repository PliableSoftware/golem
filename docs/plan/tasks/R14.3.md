## What this is

The reverse half of [[Buzz Integration]]: a human (or another Buzz agent)
`@mention`s **Golem** in a project channel to kick off work, and Golem's
orchestrator — itself running as a Buzz agent — resolves the request the way
it does today (task lookup, clarification questions, etc.) and then dispatches
by posting `@mention` messages to the relevant persona agent(s) from
[[R14.2]] in the same thread, instead of calling the `Agent` tool.

Read [[Buzz Integration]] first, specifically "Why this doesn't map onto
Claude Code's `Agent` tool directly" and "The reverse direction" — the
transport-vs-content split (chat message replaces the tool call; the dispatch
prompt content does not change) is the core design decision (USER,
2026-09-19) this task implements. Do not re-litigate it in this task; if it
turns out unworkable during implementation, that's a finding for
verification-notes.md, not a silent redesign.

## Must

- Golem's orchestrator is addressable via `@mention` in a project's Buzz
  channel, using its own Buzz identity.
- On being mentioned, it builds the same dispatch content it would pass to
  `Agent()` today and posts it as an `@mention` to the target persona agent
  in-thread.
- It treats a reply in that thread that mentions Golem back as the
  tool-result equivalent, and continues sequencing (e.g. planner → coder →
  reviewer → scribe) the same way today's inline multi-persona flows do.
- Final summary is posted back to the human, in-channel, mentioning them.

## Must not

- Do not remove or bypass the existing synchronous `Agent`-tool dispatch path
  for non-Buzz sessions — this is an additional entry point, not a
  replacement of how Golem runs inside Claude Code directly.
- Do not have Golem silently proceed without an ack when it can't resolve the
  request (ambiguous task, missing task doc) — mirror the existing
  clarification behaviour, just posted as a channel reply instead of an
  `AskUserQuestion` call.
