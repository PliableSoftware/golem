## What this is

USER decision (2026-09-19): Golem appears in Buzz as its **own peer runtime** —
`golem`, alongside `goose`, `claude`, `codex` — not as a Claude Code session
riding the existing `claude` harness with Golem's proxy in front of it.

Research since then (`verification-notes.md` §19) established that this is a
**much smaller lift than the brief originally assumed, and points the opposite
way round**. Read §19 before anything else. The short version:

- **ACP is a real public protocol** — Agent Client Protocol, by Zed Industries,
  JSON-RPC 2.0 over stdin/stdout, spec at `agentclientprotocol.com`.
- **Buzz is the ACP *Client*; Golem is the ACP *Agent*.** `buzz-acp` (a Rust
  crate in `block/buzz`) holds the relay WebSocket and spawns an agent
  subprocess over stdio. What Buzz's UI calls a "harness" is just that
  subprocess command. Nothing is registered *inside* Buzz, and nothing needs to
  be contributed to `block/buzz`.
- So "Golem as its own harness" = **ship a `golem acp` subcommand** that speaks
  ACP on stdio, and point `BUZZ_ACP_AGENT_COMMAND` at it.

```
Buzz Relay ──WS──→ buzz-acp ──stdio(ACP/JSON-RPC)──→ golem acp
                                                         │
                                                    buzz-cli
                                                 (messages send, …)
```

This is the foundational task. R14.2 (identity provisioning) and R14.4
(orchestrator dispatch) both assume `golem acp` completes a turn. Ship the
plain-conversation case only.

## The protocol surface, exactly

`buzz-acp`'s own README (§ "Using Any ACP Agent") states the whole requirement.
Four things:

1. Accept `initialize` and return a result.
2. Accept `session/new` with `mcpServers` and return a `sessionId`.
3. Accept `session/prompt` with a text message and stream `session/update`
   notifications.
4. Return a `stopReason` (`end_turn`, `cancelled`, `max_tokens`, …).

Everything else in ACP — `session/load`, `session/set_mode`, `fs/*`,
`terminal/*`, `elicitation/*`, `session/request_permission` — is optional and
capability-gated. Do not implement any of it in this task.

## Implementation plan

### Dependency

`@agentclientprotocol/sdk` (npm, official TypeScript library). Use the fluent
`agent()` entry point; `AgentSideConnection` is deprecated. It is pure
TypeScript over JSON-RPC with **no native bindings**, so it satisfies
`CLAUDE.md`'s "no heavyweight native deps in default install" — but it does
become a runtime dependency of the default install, because `golem acp` is a
CLI subcommand. **Check its installed weight before committing to it** and
record the number.

*Trade-off worth flagging:* the required surface is four methods. Hand-rolling
JSON-RPC-over-stdio is roughly 300 lines and adds zero dependencies, at the
cost of tracking ACP's schema by hand as it moves (the spec has a v2 draft).
Take the SDK unless its weight is genuinely objectionable; say which, and why,
in the PR.

### Files, in the order to touch them

1. **`src/buzz/types.ts`** — Zod schemas for the four inbound message shapes.
   `buzz-acp` is an external boundary, so validate at it per `CLAUDE.md`;
   trust the types inward from there. Keep these local to `src/buzz/` — **do
   not add anything to `src/interfaces/`**, which is frozen.
2. **`src/buzz/acp-session.ts`** — the session registry: `sessionId` →
   `{ cwd, mcpServers, personaId, history }`. `session/new` mints one; a
   session outlives a turn, and `buzz-acp` may `!rotate` it away underneath us.
3. **`src/buzz/acp-turn.ts`** — runs one turn: takes the prompt text, feeds it
   through Golem's existing pipeline and routing (redaction, compression,
   provider selection), emits `agent_message_chunk` `session/update`
   notifications as output arrives, and resolves to a `stopReason`. Model
   selection reads `inference.personas.<id>.model` via `personaModel()` in
   `src/inference/personas.ts` — **never hardcode a model here**.
4. **`src/buzz/acp-agent.ts`** — wires 1–3 to the SDK's `agent()` over
   `process.stdin` / `process.stdout`. **Nothing may write to stdout except the
   JSON-RPC stream** — logging goes to stderr or a file, or the protocol
   corrupts. This is the single most likely way to break this task.
5. **`src/cli/commands/buzz.ts`** — the `golem acp` subcommand (plus a
   `--persona <id>` flag R14.2 will use), registered from
   `src/cli/program.ts` alongside the other command modules.
6. **`src/buzz/harness-definition.ts`** — emits the Buzz Desktop "Bring Your
   Own Harness" tier-3 JSON (`{"id":"golem","label":"Golem","command":"golem",
   "args":["acp"], …}`) for `<app-data>/custom_harnesses/golem.json`. `golem`
   is confirmed available — the reserved namespace is tier-1 (`goose`,
   `claude`, `codex`, `buzz-agent`) plus the tier-2 presets. **Emit the file
   only; installing it into Buzz's app-data directory is R14.2's job.**
7. **`tests/unit/buzz/`** — a scripted fake ACP client driving the four
   methods, plus recorded-shape tests for the JSON-RPC envelopes. `block/buzz`
   tests its own side this way (PR #7359 adds "a scripted fake agent"); the
   mirror image is how Stage 1 is verified without a relay.

### Non-obvious constraints, all confirmed

- **`BUZZ_ACP_IDLE_TIMEOUT` defaults to 620 seconds and resets on any agent
  stdout activity.** A turn that thinks quietly for over ten minutes is
  cancelled. Streaming `session/update` is therefore the keepalive as well as
  the UX — a batch-then-emit implementation will be killed on long turns.
  `BUZZ_ACP_MAX_TURN_DURATION` (7200s) is the hard cap.
- **`BUZZ_ACP_AGENT_ARGS` splits on commas**, so the persona flag arrives as
  `acp,--persona,coder`. Args carrying values use `-c,key="value"`.
- **`buzz-acp` injects `BUZZ_RELAY_URL`, `BUZZ_PRIVATE_KEY` and
  `BUZZ_AUTH_TAG`** into the subprocess environment. `BUZZ_PRIVATE_KEY` is a
  Nostr secret key — it must be in Golem's redaction set before any turn runs,
  and must never reach a log, a telemetry record, or the KB.
- **`session/new` carries `mcpServers`**, the Buzz-managed MCP server among
  them. Accept and store it; this task does not have to call those servers, but
  it must not reject the parameter.
- Cross-platform per `CLAUDE.md`: `node:path`, argument-array spawn, no shell
  string interpolation.

## Must not

- Do not implement persona-specific or orchestrator-specific behaviour — that
  is R14.2/R14.4, and coupling it here makes both unverifiable alone.
- Do not silently reuse the `claude` harness under a `golem` label.
- Do not write into `block/buzz`. Nothing about this requires a PR there, and
  §19 records why.
- Do not build on `--persona-pack` / `--persona` / `--workdir` on the Buzz
  side: that is PR #7359, **open and unmerged**. Golem's own `--persona` flag
  is a different thing and is fine.
- Do not print anything to stdout other than protocol traffic.
