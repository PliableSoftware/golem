## Problem

`trimOutput` (line 166) and `fileBackend.get` (line 448) both use `.trim()`, which strips ALL leading and trailing whitespace. The encoding layer only adds a trailing newline (`${secret}\n` in fileBackend.set, or the CLI helper's single trailing newline), so the correct inverse operation is to strip one trailing `\r?\n`, not all whitespace.

If an API key or password contains intentional leading/trailing whitespace (rare but possible for passwords, some legacy tokens), the credential would be silently corrupted on round-trip.

## Fix

Replace `.trim()` with `.replace(/\r?\n$/, "")` (strip exactly one trailing newline) in:
- `trimOutput` (line 166): `s.replace(/\r?\n$/, "").trim()` → `s.replace(/\r?\n$/, "")`
- `fileBackend.get` (line 448): `.trim()` → `.replace(/\r?\n$/, "")`

Keep the `=== ""` empty-check (a secret of only newlines should read as null/absent).

## Outcome (2026-10, fix/credential-trim)

**Backends are byte-exact.** Reads strip exactly one trailing `\r?\n` (`stripOneNewline`); a
newline-only value reads as absent; libsecret and the DPAPI batch decode strip nothing; DPAPI encrypt
no longer `.Trim()`s the plaintext (pinned by a static test). Line numbers above were stale; every
`trim()` on a secret path was changed.

**Judgement lives at the edges, in `src/credentials/validate.ts` and `store.ts`.**

- Gateway key INGESTION (piped, prompted, `add --login`; `normalizeGatewayKey`) trims ALL leading and
  trailing whitespace (spaces, tabs, NBSP, Unicode spaces, BOM, any number of newlines): an API key
  never has any, which makes cmd's `echo KEY |` and `key\n\n` harmless. Interior spaces are kept. It
  then REFUSES, without echoing the key, any control character (CR/LF/TAB/DEL/C1), U+FEFF, or code
  point above U+00FF (zero-width space, curly quotes: undici rejects these one request at a time, even
  with `--no-probe`). Every refusal is an `InitError`, exit 2, ending "Nothing stored."; newline-only
  stdin says "no key was provided on stdin".
- READ SIDE: the store treats a stored value as malformed when it has a control character or BOM
  (every kind), and, for gateway accounts only, a code point above U+00FF or leading/trailing
  whitespace. Portal tokens (JSON) and Buzz secrets (hex) get only the universal check. The store tells
  kinds apart by account name (`portal-oauth`, `buzz:`; pinned by a test), the rest are gateways.
- A malformed value is NEVER "absent": it stops the chain (no fall-through to a stale plaintext file),
  `resolve` throws `MalformedCredentialError` (no value in the message), and `status` /
  `resolveManyDetailed` report a fault with `malformed: true`. `mintIdentity` therefore refuses to
  overwrite a malformed Buzz secret instead of re-minting (an irreversible identity rotation); only
  `rotateIdentity` re-mints. `resolveMany` stays non-throwing for the proxy-start path.
- Remedy text per kind: gateway `golem gateway login <id>`; portal `golem team link`; Buzz says Golem
  will not overwrite it and to remove the credential and re-provision only if rotating is intended
  (`rotateIdentity` still has no CLI, R14.2). A malformed portal token reads as present-but-unusable and
  the token read surfaces the error rather than "not linked".
- VISIBILITY: proxy start prints `warning: credential "<id>" not loaded — ...` for each malformed
  account (it still starts for the keyed ones); `golem status` prints `Credential: "<id>" NOT USABLE`;
  `golem gateway list` already shows `key_faults`. The probe reports an undici malformed-header error
  as `rejected` (malformed key), not `inconclusive`.

**Known gap, no behaviour change:** a stored secret ending in `\r` comes back without it from the file
and macOS backends but with it from single-key DPAPI. A CR is a control character, so only a
hand-edited store is affected and it is reported as malformed on read.

**Not covered:** `--value-file` in `src/cli/config.ts` feeds config values, not credentials, and still
trims. Live PowerShell is unverified off Windows (shim only). `golem status` now reads the active
gateway's stored key (a macOS keychain ACL prompt is possible, as at proxy start).
