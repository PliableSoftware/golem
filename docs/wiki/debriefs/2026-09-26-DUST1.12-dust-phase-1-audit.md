# Dust Phase 1: eleven audits, one baseline

## Outcome

Phase 1 of the dust initiative is done. Eleven read-only audits (DUST1.1–DUST1.11) ran in
parallel, each in its own worktree, and each checked one subsystem's documented claims against
the code at `fd3aedc`. Every audit committed one findings note under `docs/plan/audit/dust-1/`.
DUST1.12 merged the eleven branches into `dust/phase-1` with no conflicts (one note per branch,
as briefed) and wrote `SUMMARY.md`. SUMMARY is the single baseline for Phase 2 (wiki and spec
rebaseline) and Phase 3 (fixes and refactors).

- **800 table rows, 791 classified:** 436 shipped-and-matches, 194 drifted, 70 partial, 43
  not-started, 48 dead-or-superseded. Roughly half the documented surface still matches the code,
  and a quarter has drifted.
- **38 cross-partition duplicate groups** fold 92 rows into 746 distinct features. Twelve of those
  groups disagree on classification. They are listed for the human, not resolved.
- **105 distinct gaps, 83 with no task doc.** Phase 2 has to write those task docs or retire the
  claims.
- **Five HIGH security items were flagged for an out-of-band fix before Phase 3.** A sixth is
  unreachable for now and is a gate on R14.2.

## The HIGH items

1. **The npm package was silently renamed, and the old name is unclaimed.** `golem-run` became
   `@pliable/golem` inside `2fc7cd2`, a `fix:` commit about gateway model shapes. Three
   partitions found this without coordinating (DUST1.1, DUST1.8 and DUST1.11). On 2026-09-26 the
   registry answered 404 for `golem-run`, while `@pliable/golem@0.54.2` was published. The update
   check, both installers' npm rung, `ps` detection, README, CLAUDE.md and the spec all still name
   the old one. That is a working breakage (update checks nothing), and the unregistered name is
   also a squatting target.
2. **`POST /__golem/pipeline/false` turns redaction off with no authentication.** It has no Origin
   check and no persistence, and no status surface shows it (probed with a forged Origin). This
   violates the [[Redaction Stage]] hard rule through a door that ADR-0004 does not list.
3. **Pipeline fail-open.** Any throw in `process()` forwards the original, unredacted body. That
   includes a failed CCR blob write, which is reachable in production.
4. **A committed `team.portal_url` receives the member's portal bearer token.** A hostile repo can
   collect it on the next `golem init` or `golem team sync` (see [[Team Layer]]).
5. **The autonomy classifier treats newline-chained Bash as `read`.** At `assisted`, `ls\n<anything>`
   is auto-allowed, which breaks the [[Autonomy Gate]]'s "unknown never auto-allowed" invariant.
6. **The Buzz keygen parser swaps the public and secret keys.** It would commit the secret to the
   manifest, but no CLI reaches that path yet.

## Key lessons

- **A rename inside an unrelated commit is invisible to every review surface that reads commit
  messages.** Three auditors found the package rename only because they read `package.json`
  against the prose. A `name` change should need its own commit and a check that fails when the
  docs, installers and update path disagree with it. Compare [[Release Pipeline]], which assumes
  the name is fixed.
- **Four unfinished renames account for most of the drift:** slider to dials, `account` to
  `gateway`, the Decision 27/35 MCP tool names, and the package name. Each was changed in code,
  and the prose, comments, tests and done-task gates were never swept. Phase 2 can clear a large
  share of the 194 drifted rows by rebaselining those four terms. The general lesson: a rename is
  not done when the code compiles.
- **Redaction has more off-switches than the docs admit.** `bypass_all` (documented), the
  `x-golem-bypass` header, the admin endpoint, fail-open, and the in-place plugin mutation all
  forward raw bytes. Each looked reasonable when added. Only a partition that owned "every path
  a byte can take upstream" saw them together.
- **Parsers that skip what they cannot read hide work.** `PlanTaskStore.list()` silently drops
  four task docs with `size: XS`, including an open bug (R8.29). A lenient parser needs a loud
  count of what it skipped (see [[Plan Tasks]]).
- **Self-reported tallies drift from their own tables.** Two of the eleven notes (DUST1.3 by one
  row, DUST1.6 by ten) reported counts that their own tables contradict. SUMMARY recounts from the
  tables mechanically. Any future multi-note roll-up should do the same rather than add up the
  headers.
- **Redaction touches the audit itself.** Agents reading through the proxy saw placeholders in
  place of real bytes, and some copied them. Fourteen commit trailers carry a literal
  `[REDACTED:email:N]`, and one note names a wiki page by its placeholder. An auditor has to check
  byte-wise before quoting, as DUST1.1 did.
- **Parallel agents stayed isolated because each had its own worktree.** No branch touched
  another's file, so the merge was clean. The [[Architecture]] of the audit (one partition, one
  note, one branch) made the merge mechanical.
