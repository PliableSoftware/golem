# DUST2.19: three hosted-session gaps

Closes DUST1.10 rows 18, 20 and 21 for [[Hosted Session]] and [[Session Transport]].

## Outcome

- **Remote turns are marked locally.** `isRemoteOrigin(origin)` (anything but `local`) drives a `REMOTE` label in `golem session host log` and a `[remote:<id>]` line on the `session host serve` terminal, through a new `onRemoteTurn` transport option called after the audit line is durable and the turn delivered.
- **A hosted session parks at the usage limit.** The host gate, a deliberately separate implementation from the guest gate, now runs the same `decideSnoozeNudge` decision with the same `PARK_EXEMPT_TOOLS`, so `snooze` stays reachable and its `note` files the durable task. A `parked` lifecycle line is written. The stale-feed warning is not repeated: it addresses a human and a hosted session has none.
- **A device can interrupt a running turn.** The route already existed but hosted sessions never supplied `interrupt`, so it answered 501. `HostedSession.interrupt()` logs `interrupted by device <id>` (before the kill), kills the runner and marks the exit; the endpoint answers `stopped:false` when nothing was running, and the bus publishes `turn_end {cancelled: true}` then `ended`. The session does end: only a process kill stops a turn on Windows (verification-notes section 142), and the reason text says so.

## Lessons

- `SessionTurnEndEvent.cancelled` is an additive change to the frozen `src/interfaces/session-events.ts`; nothing existing changes shape. Dependent clients (the chat page was updated) should render it.
- The conversation store contract was left alone: origin lives in the host log, not in stored turns. A device-originated first turn is visible in the log but not on the `serve` terminal, which only sees follow-up turns through the transport.

## Not done

- P3 (does Decision 61 reach hosted sessions) and permission answering (R13.9) remain open, as scoped out.
