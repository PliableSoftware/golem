# Dust batch 2: PRs #296 to #318

Twenty-one tasks closed in pull requests #296 to #318 (the marketing refresh #316 is covered under open exceptions), continuing the work in [[Dust Method]] and the earlier debriefs for the Dust phases. The hard-rule and data-integrity changes (redaction, the proxy request path, the vector store lock, the settings cascade, the release script) and the new team text channel were reviewed independently, in one to three rounds. The rows are in `docs/plan/SHIPPED.md`.

## Outcome

- **Redaction and the proxy path.** DUSTSEC.24 bounded the named redaction rules on pathological input, DUSTSEC.23 made the request redaction walk time-sliced so a 32 MiB body no longer freezes the event loop (worst stall about 10.6 s before, about 100 to 130 ms for the walk itself), and DUST2.23 made redaction-off unrepresentable in a caller-built policy. See [[Redaction Stage]].
- **Knowledge.** The vector store lock break is fenced and the heartbeat checks the owner (`vector-store-lock-and-outside-watch`), files outside the project get `external:` keys, DUST2.14 added a leader-elected watcher so wiki and `watch_paths` writes reach the index, DUST2.15 added alias lookup and a `fetch` that serves every hit kind, DUST2.13 gave the web cache real freshness rules. See [[Knowledge Base]] and [[Web Cache]].
- **Config.** DUST2.16 honours `default!` as a floor (the registry is empty, so nothing is pinned), and DUST2.22 added one bounded, fenced team note for the coder worker lane. See [[Settings Cascade]] and [[Team Layer]].
- **Plugins, tasks, release, credentials, dashboard.** DUST2.11 ([[Plugin Seams]]), DUST2.12 ([[Plan Tasks]]), DUST2.21 and its symlink fix ([[Release Pipeline]]), R8.29 credential trim, DUST2.17 selection log, DUST2.18 usage tiles, and `skill-opt-out-sticks` ([[Skill Opt-Out]]).
- **Small fixes:** quoted roadmap titles, the stale "committed to git" claims, `golem wiki check` for unlisted pages of every type, the invented compression level in the session report, spawn-failure detection, and the dust3 leftovers.

## Default rules applied

- **Doc follows shipped code** decided the wording fixes: the "wiki writes are committed" claim was corrected at its generator, not in the output, and the PR for it left the dated history (WIKI.md preamble, Decision 44, debriefs) alone.
- **Redaction is never weakened** decided DUST2.23 Probe 1: exempting more `=`/`+` path-like tokens would have stopped an over-redaction, but the task's own rule says output for unchanged inputs must not change, so the first attempt was reverted and `redaction-rules.ts` is byte-identical. The existing behaviour is pinned by a test named "accepted over-redaction: DUST1.1 headline 9". Stopping it needs its own user decision.
- **A leak loses to idempotence** decided DUSTSEC.24, see below.
- **No key is pinned by default:** `default!` can only make a boolean stricter or equal, and pinning removes a capability from every user, so the registry shipped empty and the choice of keys is left to the user.

## Open exceptions

- **DUSTSEC.24 accepted weakenings:** a separator-free card glued to a hex-only token (`a<card>`, `<card>f`, `ID=abc<card>`) is no longer redacted; an email local part beyond 128 characters keeps only its head; a second redaction pass can over-redact a glued scheme with a placeholder in the password position (nothing leaks).
- **DUSTSEC.23:** the stall is one slice plus the largest call that cannot be sliced (parse, duplicate-key scan, final `JSON.stringify`, one huge string), and a 32 MiB non-JSON text body is still one synchronous scan.
- **Review rounds waived by the user:** DUST2.14 had one review and a second round was waived; the third round of fixes for DUST2.22 was not re-reviewed. Both are stated in the PR bodies.
- **Vector store lock:** a few-millisecond-lag interleaving of clearers can still produce two breakers (bounded to an aborted write by the fence), and nothing there has run on real Windows.
- **Release script:** that the asset assertion fails on a missing asset, that the version output expands to the right name, and that `npm pack` produces `pliable-golem-<version>.tgz` are only proven by a real release. The renames are sequential, not one transaction.
- **DUST2.22:** free text cannot be proven harmless; the fence and the worker lane's bounded authority are the defence, not the filters.
- **DUST2.13:** when the raw pre-fetch fails or `knowledge.webcache_fetch_raw` is off, the PostToolUse hooks cannot see response headers and may store a `no-store` page.
- **Marketing drafts:** the refresh in #316 was fact-checked once (verdict CONCERNS, 12 text findings) and the 12 fixes were not re-checked; several ledger rows were neither re-read by the author nor spot-checked. It was written before #315, #317 and #318 merged, so it lists DUSTSEC.23, the team prompt and the wiki watcher as not shipped. Nothing is published.

## What review caught

- **A redaction leak behind a fake placeholder, introduced by a fix.** In DUSTSEC.24 the second review round was answered with an idempotence exemption on the connection-password rule, and that exemption was accepted. The third review found it caused a confirmed leak: a password hidden behind text that looked like a placeholder, 1,129 to 1,885 leaks per 50,000 fuzz texts. The exemption was removed so the password lookahead is exactly the original's. Earlier rounds had found a password leaking behind a scheme over 128 characters, a single trailing bad `-----END ` line making the private-key scan quadratic again, and a card exemption that was too broad. The final evidence is a differential against the old rule over four seeds of 50,000 texts: 0 leaks.
- **A release script that silently did nothing.** DUST2.21 made `release.mjs` and `sync-version.mjs` run only when invoked directly, by comparing `process.argv[1]` with the module path. Under a symlinked path (macOS `/var` to `/private/var`) the comparison is false, so the script exited 0 having bumped nothing. The advisory macOS job caught it (#310); the Linux and Windows legs did not.
- **Lock-break races.** The original breaker renamed the lock away and tried to put it back, leaving a vacancy where a third process could take the slot. Review found that, the missing write fence, a Windows retry window, an orphaned take-over, a symlinked project root becoming `external:`, and a symlink into a project subdirectory getting a base above the project (a regression within the PR). Two tests that passed on the old code were fixed or relabelled as guards.
- **An orphaned `mcp serve`.** The DUST2.14 review found the server outliving its client; timers are now unref'd and it closes on transport end, stdin end and SIGTERM, SIGINT and SIGHUP. The same review found a stale-index risk from a session on an old embedder (a manifest signature check now runs before every batch) and files recorded as indexed with no chunks. All eleven findings were fixed. The resumable first build was also reworked in review (uncapped resume, manifest read safety).
- **An unhandled `EPIPE`.** R8.29: `run()` had no `error` listener on the helper's stdin, so a helper that exited before reading it took the process down. It showed up as an Ubuntu shard failure on the PR's first push, and the fix has a regression test that fails on the old source in 3 of 3 runs.
- **A team-prompt fence that leaked.** DUST2.22 reviews found the fence marker slipping through in lookalike spellings and invisible characters (Cyrillic lookalikes, combining marks, zero-width and bidi characters), plus role headers behind invisible prefixes and several URL and IP forms. The structure checks now run on a confusable-folded skeleton and the gate is an allow-list. A team row marked enforced was also being reported as enforced, and the resolved config object carried refused values; both fixed.
- **Smaller:** a generator-based async redaction walk that refused bodies at about 2,200 nesting levels (DUSTSEC.23; now iterative); a plugin log line cut before redaction that could leak half a key crossing the cut (DUST2.11); `golem plugin --check` printing nothing and exiting 0 for a never-settling stage; a rename that threw after taking effect not being restored by the release script's first draft; `FileWikiStore.upsertPage` echoing a smuggled `aliases` field (found by the new contract test).

## Lessons

- **Review the fixes, not only the change.** The worst defect of the batch was added by a fix to an earlier review finding. A fix to a hard-rule file is new code and needs the same scrutiny, and a round of fixes that no one re-reads (DUST2.22's third) is the shape that missed it.
- **Fuzz against the old rule.** A differential against the previous implementation, with placeholder-bearing and adversarial shapes, is what found the leak; the hand-written cases had not.
- **A silent exit 0 is the worst failure for a script.** The entry-point check passed every test that ran the script by its typed path. It took a different filesystem layout to show it.
- **Platform legs catch different things.** The advisory macOS job caught the symlink bug. The Windows leg caught the torn-cache test twice (#290, then #292, because pacing the reader was not the whole fix). The first push of #300 failed an Ubuntu shard on a real unhandled `EPIPE`, not a flake.
- **Some CI gate failures were the new test, not the code.** The DUSTSEC.23 stall and nesting assertions were rewritten to hold across runners (portable depth, a stall bound that reflects the unsliceable `JSON.stringify`), and two tests had to build a placeholder-shaped string at runtime so the repo's own diff stays clean (DUST2.11, DUST2.22).
- **Say which tests are guards.** Some tests pass on the old code by design: an absence check, a clean-tree exit 0, a vacuous "never rewrites the committed document" (DUST2.12 lists four of 30; 26 fail on old source). DUST2.17 had six of twelve fail without the source change, and two of the vector store tests turned out to pass on old code and were relabelled. A test that cannot fail on the old code is a guard and should be named as one.
- **Never `git stash` with parallel worktrees.** `refs/stash` lives in the common git directory, so it is shared by every worktree of the repository: one agent's stash is visible to, and poppable by, another. During this batch a stash was popped. Commit on your own branch instead; the `golem-parallel-agent-isolation` rule already covers worktrees, branches and `node_modules`, and this adds the stash.
- **Fact-check the marketing, then re-check the fixes.** The refresh was checked once, twelve text findings were fixed, and the fixes were not re-checked. The REVIEW.md header says so, and the drafts are stale again after #315, #317 and #318.
- **State limits as the PR bodies do.** Each shipped row names what it does not do, so a later reader does not have to rediscover it.
