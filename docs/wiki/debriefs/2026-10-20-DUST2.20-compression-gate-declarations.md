# DUST2.20: compression gate declarations

## Outcome

- Every lossy stage is declared in `LOSSY_STAGES`: gate level, caching-upstream gating, whether the R2.6 force flag lifts it, sidecar need, recovery, and where `pipeline.ts` enforces it. A test checks each row against `stagesForCompression`, against `resolveEffectiveCompression`, and fails when a `StageConfig` field is neither declared lossy nor listed non-lossy. See [[Compression Levels]].
- `HEADROOM_LEVEL_MAPPING` records what levels 2 and 3 hand Headroom and a test pins it to the worker presets. The audit row asked for a per-content-type mapping; Headroom's router detects content types itself, so the docs now say Golem sets classes and recent-history depth, not a codec per type.
- `FileResultCache` is stamped before the read and invalidates on mtime, ctime, inode or size change or a vanished file. It is not wired into the proxy: request bodies carry no file path for a tool result.
- Unified Headroom MCP surface is retired, not built: `expand` and `search` cover retrieve and memory; only `stageSavings.semantic` reaches `stats`.

## Lessons

- A declaration that nothing enforces drifts; the test over `StageConfig` keys is what makes a new stage field force a new row.
- Headroom's stale-turn drops stay unmarked (C4), so `recovery: "none"` for the semantic stage is the honest value.
